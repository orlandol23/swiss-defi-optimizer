# Security and architecture audit, September 2026

Audited state: `75cf8f2` on `main`, 2026-09-05, immediately after the merge of
the ERC-4626 conformance work. Statuses below are current as of 2026-09-07 and
name the pull request that closed each item, so the file can be read against
`git log` rather than trusted.

This is one of six repositories audited in the same pass with the same method.
The cross-repository patterns are listed first because the fixes repeat.

## Method

One read-only reviewer per repository, in parallel, with no calls to paid or
external APIs. This repository's reviewer wrote three malicious strategy
contracts and executed them against an isolated copy of the vault, which is how
the first finding below moved from "suspected" to "proven". On top of that, one
deterministic check across all six: no `.env` tracked at any point in history,
`.gitignore` covering it, zero secret patterns, zero `pull_request_target`.

Every HIGH finding was verified in the code by the author of this file before
it was written down. Reviewers also reported hypotheses they then refuted
themselves (the `maxMint` drift here), which is the behaviour of a reviewer who
is not inflating.

## Patterns shared with the other five repositories

1. **CI hygiene was identical everywhere.** No workflow declared
   `permissions:` (6/6); every action was on a mutable tag (6/6); one
   third-party action with no recent maintenance received a write token
   (`lcov-reporter-action` here). `permissions: contents: read` landed in all
   six. SHA pinning of third-party actions is decided (see Decisions) and open.
2. **Documentation asserting what the code does not do**, in all six, measured
   against the rule the repositories themselves adopted ("built vs designed",
   "honest scope"). Here: `TESTING_GUIDE.md` expected "No issues found" from
   Slither and coverage above 90% (it is 66%).
3. **A Slither gate that was decorative** (`crytic/slither-action@v0.4.1`
   installs `slither-analyzer 0.11.4` on Python 3.9, which ignores the
   `fail-on` threshold). Found and fixed here first, then found again in
   ai-dlh for the same reason.

## Decisions taken by the owner, 2026-09-06

Recorded here because they change the contract or its public promise. Each one
is a roadmap item until the PR that implements it links back to this row.

| Topic | Decision | Reasoning |
|---|---|---|
| Owner power (H2) | `Ownable2Step`; README states plainly that the owner can move all funds; **no timelock now**. | Two-step transfer removes accidental loss of control, the real risk of a portfolio project, in ~15 lines. A timelock changes the whole operating model (every strategy change waits) and belongs on the roadmap as a feature. Silence was the part that was not acceptable: a DeFi reviewer looks for the owner's reach first. |
| A strategy that stops paying is stuck forever | Implement `emergencyDetachStrategy()`. | `setStrategy` drains the old strategy before switching; if the old one reverts, the switch reverts, and `shutdown` does not collect funds. ~20 lines, emits an event recording the loss in `totalAllocated` instead of hiding it. The README documented the accounting overstatement but not the undetachability, which is the worse problem. |
| `maxWithdraw` ignores liquidity | Declare the exception in `ERC4626-CONFORMANCE.md` now; limit by liquidity in its own PR later. | EIP-4626 requires "maximum without reverting", and the vault says 1000 where it can deliver 100. Limiting is correct but changes maths that 18 conformance tests pin, right after the repository stabilised them. |
| Deposit rounding to zero shares | `if (shares == 0) revert`. | With the OZ virtual offset the theft is not profitable, so "limitation" in the README was honest, but the depositor loses 100% and the transaction reports success. The revert changes nobody's maths. **Fixed**, PR #7. Seed deposit at deploy is a separate, open decision. |
| SHA-pin third-party actions | Pin `romeovs/lcov-reporter-action` by SHA. `actions/*` stay on tags. | The lcov action receives `issues: write` and `pull-requests: write` and is a third-party repository with no recent maintenance. First-party GitHub actions cost real maintenance to pin for little gain. |

## Medium and low, apply-only

No decision involved; each line is one commit.

- [ ] `PriceConverter`: `feed.decimals()` is inside the `try` block rather than the guarded expression, so a revert escapes and `isPriceStale` reports "fresh" for an unreadable feed. Move it into the expression; reject `decimals > 18`.
- [x] The reentrancy test was `expect(true).to.be.true` and the fixture "strategy" was an EOA, leaving `_withdrawFromStrategy` at 0% coverage. `ReenteringStrategy` added in PR #7; `MockStrategy` / `RevertingStrategy` still to add.
- [ ] `TESTING_GUIDE.md` carries four false statements (Slither "No issues found", coverage above 90%, frontend steps). Replace with real output; remove the frontend steps.
- [ ] `scripts/deploy.ts`: the Sepolia USDC address is hardcoded with no provenance and differs from Circle's canonical one; the `else` branch deploys mocks on any unknown network. Explicit allowlist with `throw`.
- [ ] `AssetsAllocated` / `AssetsWithdrawn` events do not index the strategy address.
- [ ] `README.md` says "storage packing" and there is none (the `bool` sits three slots after the `address`).
- [x] `package.json` `repository.url` pointed at a local proxy (`http://local_proxy@127.0.0.1:.../`), leaking the environment and breaking the link. Fixed in the same PR as this file.
- [ ] Informational `npm audit` step over the full tree: 20 high findings in tooling, invisible today to the machine that holds `DEPLOYER_PRIVATE_KEY`.

## How to keep this file honest

A status here changes only in the PR that changes the code, with the PR
linked. Nothing is ticked by intention. New findings from later reviews go in a
new dated file rather than being merged into this one, so the record of what
was known when stays legible.
