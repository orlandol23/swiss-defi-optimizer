## Method

One read-only reviewer per repository, in parallel, with no calls to paid or
external APIs. This repository's reviewer wrote three malicious strategy
contracts and executed them against an isolated copy of the vault, which is how
the first finding below moved from "suspected" to "proven". On top of that, one
deterministic check across all six repositories of that pass (external
context; re-checked in this repository at head `329a2d7` on 2026-09-11): no
`.env` tracked at any point in history, `.gitignore` covering it, zero secret
patterns, zero `pull_request_target`.

Every HIGH finding was verified in the code by the author of this file before
it was written down. Reviewers also reported hypotheses they then refuted
themselves (the `maxMint` drift here), which is the behaviour of a reviewer who
is not inflating.

### Counting unit

The unit is **one row: one distinct problem whose fix is one owner action**.
Three rows bundle more than one symptom and are grouped formally rather than
split:

- **H1** is one finding: the missing `nonReentrant`, the external call before
  the state write, and the suppression that hid the issue are one root cause
  in one function. The suppression is part of the finding's history, not a
  separate defect.
- **H2** is one finding: unbounded owner reach — the drain in two
  transactions, the missing timelock and the exposed `renounceOwnership` —
  with one decision behind it.
- **L2** groups the false statements of one file into one documentation
  finding; the statements are named so none is lost.

Not counted as findings: the owner decisions of 2026-09-06 (decisions, not
defects; each maps to a row — owner power → H2, stuck strategy → M1,
`maxWithdraw` → M2, zero shares → M3, SHA-pinning → L7); the first-depositor
question named inside M3 (a design decision, `ROADMAP.md` Phase 3); and the
`maxMint` drift hypothesis from *Method* (the reviewer refuted it, so there is
no defect to count). **M6** and **L8** were fixed during the pass before the
audited snapshot was taken; they stay in the table, marked as such, because
the pass observed them.

Severity, assigned per row: **High** = on-chain exploit or direct loss of
funds or control. **Medium** = incorrect behaviour with realistic loss,
denial-of-service or reporting impact, or a safety control that does not work.
**Low** = quality, ergonomics or documentation with no direct fund risk.
**Critical** = loss of funds with no owner involvement and no mitigation;
none was found.

Recorded here because they change the contract or its public promise. Each one
is a roadmap item until the PR that implements it links back to this row.
Decisions are not findings: each one belongs to a row of the summary — owner

| Topic | Decision | Reasoning |
|---|---|---|
| Owner power (H2) | `Ownable2Step`; README states plainly that the owner can move all funds; **no timelock now**. | Two-step transfer removes accidental loss of control, the real risk of a portfolio project, in ~15 lines. A timelock changes the whole operating model (every strategy change waits) and belongs on the roadmap as a feature. Silence was the part that was not acceptable: a DeFi reviewer looks for the owner's reach first. |
| A strategy that stops paying is stuck forever | Implement `emergencyDetachStrategy()`. | `setStrategy` drains the old strategy before switching; if the old one reverts, the switch reverts, and `shutdown` does not collect funds. ~20 lines, emits an event recording the loss in `totalAllocated` instead of hiding it. The README documented the accounting overstatement but not the undetachability, which is the worse problem. |
| `maxWithdraw` ignores liquidity | Declare the exception in `ERC4626-CONFORMANCE.md` now; limit by liquidity in its own PR later. | EIP-4626 requires "maximum without reverting", and the vault says 1000 where it can deliver 100. Limiting is correct but changes maths that 18 conformance tests pin, right after the repository stabilised them. |
| Deposit rounding to zero shares | `if (shares == 0) revert`. | With the OZ virtual offset the theft is not profitable, so "limitation" in the README was honest, but the depositor loses 100% and the transaction reports success. The revert changes nobody's maths. **Fixed**, PR #7. Seed deposit at deploy is a separate, open decision. |
| SHA-pin third-party actions | Pin `romeovs/lcov-reporter-action` by SHA. `actions/*` stay on tags. | The lcov action receives `issues: write` and `pull-requests: write` and is a third-party repository with no recent maintenance. First-party GitHub actions cost real maintenance to pin for little gain. |

## How to keep this file honest

A status here changes only in the PR that changes the code, with the PR
linked. Nothing is ticked by intention. New findings from later reviews go in a
new dated file rather than being merged into this one, so the record of what
was known when stays legible.
